# 要件定義（MASAKI OS）

## 1. 目的と背景

自分（director_of_operations）の業務は、会議・CS・認定パートナー・イベント・システム改修など多岐にわたる。
情報が tl;dv、Google Drive、Slack、各種管理システム、AIツールに分散し、「何が決まったか」「誰に何を依頼したか」「自分が確認しないと進まない事項」が一覧できない。

MASAKI OS は、これらを **プロジェクトを軸に集約** し、次を1画面で把握できるようにする。

- 今日やること / 遅れているタスク
- 直近の会議と、そこで決まったこと
- 他者への依頼と、自分に確認が必要な事項
- プロジェクト別の進捗
- 自分がAIで行った作業

## 2. 実現方針（最重要・前回から変更）

**自前アプリを構築しない。追加のAPIキー・サーバー・課金を発生させない。**
既に接続済みのコネクタ（tl;dv / Notion / Google Drive）を、**Claude（この環境）から操作**して実現する。

- 議事録の生成・タスク抽出は **Claude 自身** が行う（別途 LLM API キー不要）。
- データとダッシュボードは **Notion**（既に保有）。
- 会議は **tl;dv**（既に88件）。ファイルは必要時のみ **Google Drive**。
- 新規課金はゼロ。既存サービスのみで完結する。

## 3. 基本原則

1. **保存庫とタスク管理を分離する**
   - Google Drive（任意）：録画・資料・成果物などのファイル
   - Notion：タスク・期限・担当・ステータス・決定事項・関連リンク（構造化データ）＋議事録本文
   - Notion ビュー：ダッシュボード（今日/期限超過/確認待ち/直近会議）
2. **Claudeに全部を自動実行させない**（自動 / 承認後 / 手動 の3区分。architecture.md §4）
   - 抽出結果は「下書き（未確認）」で登録し、自分が確認して「確定」するまで外部連携（依頼送付等）はしない。
3. **プロジェクトを全情報のハブにする**（会議・議事録・決定・タスク・成果物をプロジェクトに紐付け）
4. **万能AIチャットは最後**。まずデータを正しく残し、紐付け、集計できる状態を先に作る。

## 4. スコープ

### 4.1 Phase 1（MVP）— 当面のゴール

| # | 機能 | 実現手段 |
|---|---|---|
| F1 | プロジェクト管理 | Notion データベース |
| F2 | タスク管理（期限・担当・ステータス・優先度／他者依頼・確認待ちを含む） | Notion データベース |
| F3 | **会議の取り込み（tl;dv）** | Claude が tl;dv コネクタから取得（初回縦串） |
| F4 | **議事録の生成** | Claude が文字起こしから目標フォーマットで生成（初回縦串） |
| F5 | **決定事項・タスク・確認待ちの抽出と登録** | Claude が抽出し Notion に登録（初回縦串） |
| F6 | ホームダッシュボード | Notion ビュー（今日/今週/期限超過/確認待ち/直近会議） |
| F7 | 実行ログ | Notion「Automation Runs」DB（取り込み実行の記録） |

**初回縦串（最優先）= F3→F4→F5。** これを1本通すことを最初のマイルストーンとする。

### 4.2 Phase 2 以降（将来）

定期自動実行の検証・導入、リマインド（要検証：後述）、週次レポート、AI作業履歴、KPI（認定パートナー/CS）、横断検索・会議前ブリーフィング、Canva等での資料生成。

### 4.3 やらないこと（Non-goals）

- 自前アプリの構築（Next.js/Supabase/Vercel）と、それに伴うAPIキー・サーバー・課金
- Zoom API の自前実装（tl;dv で代替）
- マルチユーザー権限（自分専用）
- AI会話の全文保存（要約・成果物・履歴のみ）

## 5. 実行モデルと自動化度合い

- **半自動（Phase 1）**：Claude セッション（Claude Code Web/アプリ）で「直近の会議を取り込んで」等と指示すると、取得→生成→登録→抽出を実行する。
- **定期自動（Phase 2・要検証）**：無人の定期セッションでコネクタが使えるかを検証してから導入。使えない場合は、毎朝ワンコマンドの半自動運用を継続する。

## 6. リマインド／通知（Phase 2・費用ゼロの範囲）

- 第一段階は **Notion のビューを自分で開いて確認**（「今日／期限超過／確認待ち」）。プッシュ通知なしで運用可能。
- 定期セッションが使えれば、そこから通知を出す方式を検証（追加費用が出ない範囲で）。

## 7. 非機能要件

| 区分 | 要件 |
|---|---|
| 利用者 | 単独（自分）。Notion の該当スペースは自分が所有 |
| 認証 | Notion/tl;dv/Drive の既存アカウント。Claude 側のコネクタ接続を利用 |
| 費用 | **追加課金ゼロ**。既存サービスの範囲内 |
| 機密性 | 会議文字起こし・CS・会員情報は機密。保存対象/範囲/削除/操作履歴を定義（architecture.md §5） |
| 監査 | 取り込み・確定・削除等は Notion 側の履歴／実行ログで追える |
| 可用性 | 個人利用。定期処理を入れる場合は失敗を検知できること |

## 8. 用語

| 用語 | 意味 |
|---|---|
| 決定事項（decision） | 会議で合意・確定した事項 |
| タスク / action item | 担当・期限つきの実行項目 |
| 確認待ち（confirmation） | 自分または他者の判断・回答待ちで止まっている事項 |
| 縦串（slice） | 1機能をデータ取得〜表示まで縦に通した最小の完成単位 |
| コネクタ | Claude に接続済みの外部サービス連携（tl;dv/Notion/Drive 等） |
